# Acceleration levers

Program-level choices that shorten the path between levels. Confidence is how likely the lever is to pay off as described: Proven (about 90%), Likely (about 75%) or Stretch (about 50%).

| When | Lever | How | Confidence |
|---|---|---|---|
| To L1 | Run governance and the gateway alongside the baseline | Security, legal and platform start in week 1 instead of after the charter. Needs those owners committed before kickoff. | Proven |
| To L1 | Start from the vendor's compliance package | Use a model already covered by your data-processing terms and your existing data classification instead of writing new ones. | Likely |
| L1 → L2 | Shorten the pilot to 4 weeks | Pick pilot pods whose leads already use AI daily, and agree the pilot's success measures before it starts. | Likely |
| L1 → L2 | Run bigger rollout waves (9 pods) | Two champions per wave pod and a standard onboarding kit. Needs enough licences and gateway capacity in advance. | Likely |
| L1 → L2 | Cut each wave to 3 weeks | Train-the-trainer kit, recorded onboarding and office hours, so champions don't repeat the same sessions. | Stretch |
| L1 → L2 | Have synthetic data ready before the pilot | Masked or synthetic data sets for every pilot product, so no pod waits on a data review. | Proven |
| L1 → L2 | Move products in 3 cohorts | Front-runner products start Level 2 first and climb on their own track; later cohorts reuse their templates, pipelines and lessons. Level 1 stays shared. Value arrives earlier. | Likely |
| L2 → L3 | One golden-path pipeline template | Build the pipeline, eval harness and PR environments once, then stamp them per product. Halves the per-product setup. | Proven |
| L2 → L3 | Build the eval harness and PR environments during Level 2 | The platform team starts Level 3 tooling while the waves run. Needs the enablement team at 1 per 40 engineers a level early, which adds cost. | Likely |
| L2 → L3 | Run 3 platform squads in parallel | Split per-product pipeline, eval and evidence setup across three enablement squads of about 4 people each. Adds their cost. | Proven |
| L2 → L3 | Write compliance controls as code during Level 2 | Turn the audit checklist into pipeline checks before gates are enforced, so G3 evidence exists from day one. | Likely |
| L3 → L4 | Feature flags and observability on every service during Level 3 | Canary releases and automatic rollback need both. Doing them early removes the longest Level 4 prerequisite. | Likely |
| L3 → L4 | One release evidence package for all products | A shared format for test results, scans, evals and the rollback plan, generated by the pipeline for every product. | Likely |
| L3 → L4 | Agree the evidence format with auditors at Level 3 | Auditors accept the pipeline-generated package before Level 4, so there is no review cycle at the end. | Stretch |
